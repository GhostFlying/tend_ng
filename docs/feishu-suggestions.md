# 飞书建议与本人关系

飞书建议从用户身份下可核对的其他人明确 @ 本人的消息开始。增量搜索、权限/身份核验、分页、重叠去重与检查点归 Server。事件不是授权。研判不回复、不转发、不执行任务，也不触发 Router、通知或 Issue。

## 事项和观察

同群相近的独立提及分别成卡。只有可核对的同事项关系（如指向原请求或已有后续的回复/引用）可延续卡片；同会话、同 thread 或共用一个被讨论对象本身不足以合并请求。补扫发现可核对的关系可以合并临时卡，旧链接、快照和操作回执仍可追溯。历史卡不做批量拆分或重研判。

首包一次给本人显示名和同源身份键。锚点、可读的直接父消息和直接引用按来源 ID 去重并单列，保留不可读指向。每条证据有作者/提及键、关系、创建/编辑时间和来源入口，文本截短、非文本、撤回和仅可定位会话明确标注。带本次观察截止、实际范围、可续读方向和覆盖缺口；没看到回复与尚未读到区分开。话题只选同线程的材料，普通群只选可沿回复/引用连回当前事项的材料。除锚点及其直接对象外，按相对顺序带最近的前两条和截止内最新的后四条。同群邻近但未能确定关联的材料不进首包。

## 按需补读和版本

研判按需用两类只读工具，读取已知材料或直接指向的同会话消息，或逐页翻看绑定锚点的前后文。每页受本次观察截止约束，不采用截止后才创建或实质编辑的版本，也不以不可用、静默或未查完作为结清依据。普通群邻近消息只有在能指出对象、引用或内容联系时才能支持结论。扩读已知消息只在核实为同一版本且没有冲突字段时补齐正文，保留已核实的消息位置、直接关系及来源链接。已补齐的直接引用和本轮引用状态随结论保存，初次采集的缺口不覆盖本轮证据。普通群共用一个回复父消息的邻句只作未核实背景，不能单独证明已有请求结清。编辑时间不明时只用已有的可核实版本，否则注明缺口。飞书原生接口提供父消息、根消息和话题字段，独立引用只采用原生返回的结构化指向，不从链接或正文猜测。跨群及外链正文不展开，可由用户在讨论中另行补充。Server 使用原飞书用户身份并持有凭据、范围和游标；研判 Agent 不接触 CLI、通用网络或外部写工具。独立 home 的原生 rollout 保留当时的输入、补读与结果。

空轮、重复材料、页面刷新及显示名变化不触发模型。可改变结论的消息、原文实质编辑、撤回及关键覆盖补齐才更新事实版本并合并待研判。旧判断不得覆盖已变更的材料。文案改写不撤销忽略；新进展可重显并标明变化来源。普通未选材料沿用七天保留边界。不建立群聊全文库。

## 列表和显式选择

列表至多两句独立陈述，交代谁向谁请求什么、目前轮到谁做什么，并可核对原文。有决定性缺口才单列一个具体「待确认」。区分本人明确被请求、本人承诺、其他人接手、知会、已回复、已完成、已撤回和证据不足。已回复不等于已完成，接手不自动消除本人剩余步骤，证据不足不冒充本人待办。知会/无需本人行动可从默认视图降噪，原卡及链接仍可查。

忽略按事实版本记录，可以撤销。显式附入讨论或转交主 Chat 时冻结用户所选版本、结论、必要摘录和来源链接。正文扩读与后台回读不以冲突的定位覆盖已核实的来源。同一研判版本保留原引用。后续更新不改写旧快照、不再次发消息；用户可主动把新版附到原讨论。飞书原文、研判、摘要及点击都不自动赋予执行授权，真正的用户指示与证据分开。

原生正文的提及位置和身份一同保留。同名参与者可以承担不同职责，原文改派属于事实变化，单纯显示名变化不是。已核实的普通群锚点如果成为话题根，同一卡改用新话题范围，旧容器的游标作废。旧群聊里已归组但未进入该话题的提及只保留来源去重与已选快照，不进入当前卡片、观察范围或结清依据。同会话内被明确指向的直接引用仍可单独核对。后台核实的回复关系不受首包正文条数限制，补页还可确认已提供材料的关系而不重复正文。
