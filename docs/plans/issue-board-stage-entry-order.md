# Issue 看板按实际入列时间排序

## 目标与边界

六个阶段统一按当前阶段最近一次真实进入时间倒序，Server 先排序再截页。Web 桌面与窄屏保留服务端页内顺序和现有列布局。全量、按 Chat 及仅顶层的 Issue 列表使用同一排序键；不改 Issue/Task/Run 业务阶段、Runner 协议或部署。

## 权威事实与写入范围

- 卡片自身的业务状态及最新 Task 是否存在决定终态与待安排。树内 Task 状态、最新等待 Run 的 phase、同目录的外部等待占用、已到期未消费的输入及已发布未回答的 Attention 决定运行、待推进和等待。继续使用现有整棵子树计算与优先级。
- 事实由 Router 新建/启动、Runner 领取/执行/同步及操作、Server 分配/过期/交接/停止、留言/递送及 Attention 发布/回答写入。PR/CI 观测本身不影响阶段；真正递送后若产生可执行工作，仍可以触发真实阶段变化。产物可用、子项事件等也可能经输入改变阶段。
- 同一事务内以连接本地的临时触发器收集实际变更的 Issue，沿父链去重，提交前使用和看板相同的规则比较这些卡片。只保留当前阶段、已知入口时间与必要的已安排转列证据，不追加事件历史。新卡片记录首次可见阶段；已有卡片只在阶段改变时更新入口时间。一次事务以外部可见的提交前、后阶段为准。
- 等待卡片可能不靠新事务就在子项合并窗口到期时进入待推进。在确实满足其他条件时持久保存最早有资格的输入截止时间，供读取时选择已生效的键；更早的业务变化会在同一事务撤换该证据。不需要读时写入或周期性扫描。下一次影响该卡片的业务提交会以已发生的截止时间为比较基准。
- 迁移只从当前事实初始化比较基线。未证明的历史入口保持未知，排在已知记录之后。已知同毫秒或同为未知时按不变的 Issue ID（字典序降序）打破平局。分页沿最后一张卡的时间（未知用保留值 0）与 ID 继续，旧数字光标从第一页重新开始。分页是实时视图，不冻结跨请求快照。

## 验证

用隔离 SQLite fixture 验证迁移、首入列、非转列更新、离开后重入、同毫秒和未知平局、子树优先级、截止时间和尚未到期的撤换、跨页及回放。运行 Server/协议/CLI 定向测试和 Web 检查、构建；用实际 Server 和脱敏 fixture 检查桌面与窄屏在实际翻页后保序并附截图。核对候选后直推主干，不部署。
