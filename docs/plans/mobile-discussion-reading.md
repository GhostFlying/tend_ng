# 手机 Discussion 正文可读空间

## 范围与现状

`/discussions?chat=<id>` 在手机上依次分配空间给全局标题、讨论元数据和操作、引用、正文时间线、双行编辑器与快捷键、全局底栏。只有正文在独立滚动容器中。应用的 `100dvh` 不能表示所有浏览器打开键盘后的可见区域。Safari / WKWebView 可能只缩小或平移 Visual Viewport，其他嵌入浏览器也可能一起缩小 Layout Viewport。采用 `VisualViewport.height` 和 `offsetTop`，兼容可观测的两种缩小方式，不按 UA 判断，也不修改全局 viewport meta。事件可能延迟，完全不报告遮挡的宿主不能可靠判定键盘。

参考 [CSSOM View VisualViewport](https://drafts.csswg.org/cssom-view/#the-visualviewport-interface)、[Chromium 键盘调整行为](https://developer.chrome.com/blog/viewport-resize-behavior) 和 [WebKit 的键盘平移记录](https://bugs.webkit.org/show_bug.cgi?id=311821)。

## 实施

1. 仅在讨论详情且宽度不超过现有 760px 移动断点时，用单行讨论栏替代全局标题和展开的操作行。保留列表返回、完整标题语义和直接转交。在披露面板放置改名、资料选择、归档/恢复、预览编辑及来源/回执入口。引用默认折叠，保留链接和移除操作。桌面继续直接展示这些入口。
2. 次要面板打开或页头有焦点时保留页头。手机正文按实际用户滚动的累积方向收起/展开，过滤小幅反向抖动和程序定位，切换时补偿正文的上边界位移。不重挂正文或编辑器，不改变消息跟随、深链、转交及读写逻辑。
3. 手机编辑器默认一行，按实际换行限高增长，隐藏桌面快捷键。只有讨论编辑器聚焦且可视高度显著缩小时才进入键盘布局。监听 visual viewport 的 resize/scroll，按视觉视口的上下边界约束讨论框，临时去掉导航及讨论栏。恢复时保留草稿和远离末尾的阅读锚点，原在末尾时继续显示最新条目。保留安全区处理，不改主 Chat、Issue Chat、列表或桌面行为。

## 验收

- 对同一个长标题、三条引用、足够长的合成讨论，比较改前和改后的 390×844 渲染。阅读态从正文滚动区上边界至正文滚动区下边界。键盘态把同一页面裁切到同一个模拟视觉视口，两者取交集并扣除遮挡。另核对最近消息是否可见、输入框底缘及真实渲染截图。模拟视口覆盖仅缩小 Visual Viewport、平移 viewport、Layout Viewport 一起缩小和聚焦但无键盘。
- 在 Playwright 测菜单及键盘焦点、引用重新展开、发送引用及草稿、正文向下收起/向上恢复、顶部和末尾、键盘开合前后草稿和位置、390px 横向边界，另跑真实隔离 Server 的既有桌面/移动 Discussion 和转交 fixture。没有合适真机路径则明确标记模拟和 iOS 未实测。
- 本地跑 Web 锁定依赖安装、类型、lint、格式、单测、构建及定向浏览器验证。按仓库现有 `main` 约定合入，查远端完整 SHA。交付不等 CI、出包或部署。

浏览器复跑入口为 `node web/tests/discussion-mobile-layout.mjs`。默认读取 `web/dist`，设置 `TEND_LAYOUT_BASELINE` 可加入基线构建目录，设置 `TEND_SCREENSHOTS` 可将原始截图及坐标 JSON 写入指定目录。

### 审阅回归

- 已识别键盘后保持焦点切换横竖屏，按新的布局高度推算未遮挡基线。键盘关闭时清除视觉视口约束，并验证长草稿恢复原有高度。
- 将已识别的键盘与是否应用移动样式分开。保持同一编辑器焦点时不丢弃无遮挡基线，也不要求旋转后的尺寸精确互换。验证同缩宿主的非等宽横屏、仅缩视觉视口的跨断点往返，以及两种情况下真正关掉键盘后的恢复。
- 同一讨论已经测到目标宽度的无遮挡高度时，以实测为准。加测先进入 664×300 横屏，再到竖屏打开键盘并旋转，确保横屏恢复到原实测高度时能退出键盘布局。
- 在窄屏正文变得不可滚动时自动恢复工具栏。测试紧邻下滚的消息深链不会触发收起，展开的转交历史不会随下滚消失。
- 用 DOM 顺序保持桌面改名时的 Tab 路径，移动端只改变网格排列。对比桌面的实际焦点顺序和渲染，并复跑 Discussion 与转交的隔离集成。
