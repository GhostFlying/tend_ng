# 独立新建入口与讨论归档

## 目标与边界

- 在桌面讨论侧栏把带加号的「新建讨论」按钮与最近讨论分开，只标记当前会话。移动端从现有底部导航进入讨论列表，列表同样提供新建按钮与归档入口。
- 未命名讨论显示「未命名讨论」。原创建没有标题、现标题仍等于「新讨论」时，检查持久活动证据。旧版只有改名和普通消息收件能改变讨论活动时间。活动时间变化、但没有普通消息时可确认改名，保留该标题。相同秒内改名，或与普通消息活动无法区分的旧记录，没有可靠改名证据，按旧默认处理。保留原创建请求和幂等凭据。新版不按标题文字把显式标题判为默认。
- 归档只改变列表归属。历史、引用、转交回链、原生线程、回复和原链接不变，不取消进行中的输入，不新增禁用读写规则。归档当前讨论后返回普通列表，不选择也不创建新讨论。从已归档列表打开原讨论，恢复后仍停在原链接。无删除能力，无部署；不使用真实线上讨论。
- 做完合成验收与独立候选审阅后，直接推送到 main，回读远端提交。

## 实施

1. Server 迁移新增归档标记并修订旧默认标题。普通列表默认只返回未归档讨论，`?archived=true` 只返回已归档讨论，详情返回归档标记。详情 PATCH 接受单独的 `archived: true/false`，重复设置相同值不改变活动时间，不触及其他表。CLI 与 Web 使用同一 API。
2. 列表区分普通列表与已归档列表。当前讨论提供可直接点击的归档或恢复动作，明确显示已归档状态。使用现有 Web 会话与路由。更新相关契约和 README。

## 验证

- Rust 检查从 v32 升级、默认与显式标题、创建幂等、归档筛选与状态幂等。CLI 在真实隔离 Server 上和 Web 双向验证同一个归档状态。
- 使用现有单独的临时 SQLite、合成讨论和 App Server fixture。Playwright 打开最终 Web 构建，验证创建按钮和唯一选中项、移动端导航、归档当前讨论不创建空白会话、已归档列表和旧链接、恢复后同一身份及消息和引用不变。保留实际桌面和移动端渲染图。
- 运行相关测试和锁定构建，复核最终差异及远端 main SHA。无真实模型、生产数据或部署验证。

## 审阅修订

- v32 验收分别验证明确初始标题、后续修改为不同标题、活动时间有变化且从未发送普通消息的同名改动，以及有普通消息的默认标题。草稿的内部消息不视为普通消息活动。
- 归档导航保留浏览器历史。缓存页面恢复时重新读取当前状态，不保留旧的归档按钮锁；详情发现归档状态变化时刷新最近列表。用实际启用 BFCache 的 Chromium 验证归档后返回原讨论可恢复，并保持页面打开验证 CLI 归档及恢复在详情和侧栏同时生效。
- 用合成的延迟回合验证归档不取消进行中的回复，并验证归档状态下仍可在原线程发言。
