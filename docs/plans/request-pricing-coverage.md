# 按原请求展示 OpenRouter 估算覆盖

## 目标与边界

- 沿用 #147 的 OpenRouter 快照、适用档位、分项金额、零值判断与普通输入基准。不改用量、关联、账本或采集范围。页面去掉「部分估算」，有金额就展示，另以普通次要文字显示当前范围有多少条已识别请求没有任何可用金额。可计的零仍显示 `$0`，全未计价仅显示请求数，无请求不显示费用。
- 已有金额但缺项的请求不算整笔未计价。在展开详情保留快照、模型依据、原始字段缺项、基准假设，并分别说明分项已计、缺数量和缺适用费率的请求数。费用与用量采集覆盖分开，未观测的 Run 或回合不会被猜成请求。

## 实现

1. 在已归属、去重的请求进入模型投影时，沿用同一份报价规则判断是否至少有一个可计分项或普通输入基准。已知数量为零、明确零费率、当前档位可用费率和不支持的价格条件沿用现行金额语义。不要由聚合后的各分项覆盖数推断并集。
2. 在已保存的模型小计维护可带符号加减的请求覆盖计数。沿用既有 Run、Issue 直属、子树、各系统调用来源及全局归并；未知模型行、无精确价格和不支持价格的请求全部未计价。继续沿用原有跨来源去重和冲突隔离规则。
3. Server 升级时复用 #147 的一次性价格投影迁移，由现有持久账本补齐新计数，不改账本，不读历史原件、不创建回填任务。普通 API 继续读取投影。已有的显式投影重建、后续写入和晚到补证使用同一逻辑。价格适用性变化须同步重建覆盖投影；纯金额费率变化不影响是否可计。API 新增请求级未计价数，保留旧字段兼容旧 Web。
4. 全局、来源、Issue 直属/含后代及模型共享金额与未计价展示。分项详情用独立的计入状态，无请求级标记。

## 验证与交付

- 记录 #131 的 52 条已有金额及 Feishu 四条缺模型的只读接口基线。隔离验收复用或脱敏复现计价证据，比较 #147 与候选金额，并验证多来源、原生去重、三级 Issue、重放、晚到补证、空与全未计价、计价为零、分项缺费率或缺计量和普通输入基准。
- 验证旧 schema 升级前后金额及原账本、显式重建、日常 GET 不读请求或原件。运行受影响的 Rust / HTTP / Web 检查并做候选审阅。
- 使用真实隔离 Server 与最终 Web 构建渲染桌面、手机视口，验证展开细节并交付截图。设备测试与模拟结果分别说明。遵照仓库当前 main 门禁推送，核对 `origin/main` 完整 SHA；不部署、不写生产用量，不等待未要求的 CI 或部署终点。
