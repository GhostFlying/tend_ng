# 全量对账补回已确认交付

一期 Runner 在收到持久回执后保留原结算和交付文件。全量对账按 Server 已登记的原 Task 比较两端的持久事实，缺失的结算和文件从原 Runner 补回。 [交付副本与全量补回](../server-runner.md#交付副本与全量补回)

## 隔离验证

复用已有 Rust smoke。在 Server 已建立派发、尚未收到结果时用 SQLite 在线备份取得快照。原 Runner 完成工作并取得持久回执后，从快照启动独立的测试 Server。使用 Runner 的原本地状态发起一次全量对账，核对恢复原 Task 下的留言、结算与文件。保留数据库中的结算，再移除测试 Server 的文件原件，重复对账并核对文件按原身份补齐。恢复请求读取已完成的 Run，产品的派发和执行入口各自独立。

快照保留 Server 的原派发，只模拟结算和文件缺失。Runner 的本地确认保持有效，CLI 查回一条原结算及同一份文件。

## 执行结果

先用原 smoke 二进制复现缺口。Server 恢复到原派发后的备份时，Runner 已保存原结算、文件和确认记录。只运行原待确认同步入口，Runner 直接退出，恢复的 Server 仍缺该结算。

随后给隔离 smoke 加入显式全量入口。该入口从已完成的本地 Run 读取保留数据，包含已确认记录，并使用同一 `/sync` 受理路径。测试移开原 workspace 后通过两项检查。

1. 从交付前的 SQLite 快照启动 Server，CLI 先读到原派发。全量对账后，Server 恢复原消息、Run、操作、结算和文件，CLI 下载的字节与原件相同。
2. 保留结算并删除测试 Server 的文件后，CLI 仍读到原结算，文件暂不可读。再对账恢复同一个文件身份和原内容，Server 仍只有一条结算。两次对账期间 Runner 保留原确认。

在禁用外网的开发容器中，包含原断线、丢回执与真实 tsnet 测试的整轮 smoke 通过。复跑沿用技术 smoke 的同一条命令。这里按一个 Task 补回完整数据，产品协议按 Task 范围比对实际缺项并分批传送。 [技术 smoke 复跑](rust-offline-smoke.md#复跑)

## 手工替换数据库的额外探针

用派发前的快照手工替换 Server 数据库后，试验 Server 查不到原 Task，返回请求错误。Runner 保留原结算和确认。这个探针对应 Server 的数据库恢复操作。一期同步契约从 Server 已登记的任务开始对账。 [全量对账与回执](../design-questions.md#全量对账与回执)
