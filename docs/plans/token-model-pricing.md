# Token 模型明细与 OpenRouter 参考费用

## 目标

保留全局、Issue 直属及含后代小计。按原生请求证据和模型分组，按请求应用公示价的上下文档位，显示可估算部分及缺口。仅合入 main，不部署或写入生产用量。

## 证据与兼容

- 使用同一原 thread、turn、response ID 的用量，不读取具名 Agent 当前配置、启动时计划值或线程当前默认模型。区分逐响应模型证据和原生同回合请求模型上下文。后者不能证明供应商实际响应型号，不归入已确认模型或费用。只在“模型未知”行的证据明细保留请求模型线索。模型缺失、降级未确认或证据冲突时保留用量。
- 扩展现有实时观察、原件回溯和持久投影。升级后旧投影先归为模型未知，已有回填由新版 Runner 显式重跑原回溯。仅重建可从已持久证据恢复投影，不扫描原件。普通 GET 不读取请求、原件或价格 API。
- 保留兼容缺字段和去重。计量冲突仍沿原策略结算，模型补证不制造计量冲突。

## 价格口径

取可精确匹配的 OpenRouter 模型公示标准价快照，并公开日期、对应模型标识、上下文档位及价格链接。按请求分非缓存输入、缓存读、缓存写和输出后，再归并档位小计。全局和 Issue 两页直接在模型行展示各项。推理输出已包含于输出。数据不足时只汇总确定的收费项，其余显式未知。只估算 Token，不计工具、平台费用或折扣，不代表历史或实际账单。

## 验证

原件脱敏样本和只读历史对照、重扫补证、实时互操作、冲突与重建、父子去重、缓存交叠及长上下文边界、定向回环集成、桌面及手机截图。核对远端 main SHA。

## API 与上线读回

- Server schema 45 的请求和投影 JSON 仅增加可选字段。现有计数不会重写。未经过新版 Runner 规范化回读的旧请求不会从合计反推非缓存输入。新版回读即使找不到型号也记录已检查标记，可以补齐有原始依据的非缓存输入。新 Server 兼容旧 Runner，旧 Runner 不能提供模型证据。部署新版 Server 和有原件读取权限的新版 Runner 后，使用新作业 ID 运行 `tend token-usage backfill --all` 或定向选择器，给 #115/#116 已保存的响应补充模型。不需要先重建。已有回溯作业可继续，若切换扫描器版本造成前缀身份变化，按原作业语义报告缺口并用新作业重扫。
- 每个用量范围返回 `models` 和 `estimate`。已确认模型行给出 `response_model_requests`，未知行保留 `requested_models` 请求模型线索。仅当原件同一个 `token_usage_record` 有明确 `response_model` 时计作前者。历史 Codex 原件通常没有该字段，采用较早的同 `turn_id` 的 `turn_context.model`，不穿越 Turn，也不把无响应身份的 reroute 事件猜成新模型。这个类别只证明当时原生请求上下文，不证明供应商的响应型号，不纳入估价。模型无证据或不一致归入模型未知；同键的模型变动不会隔离有效用量。
- `estimate.usd` 是十进制美元字符串，`null` 表示没有可用估算。金额非空且 `partial` 为真时只合计能估算的部分。价格覆盖只针对已报告请求，不意味着整个 Run 用量完整。价格明细按档列适用的 Token 数、字段覆盖、美元/百万 Token 费率及对应参考金额。
- 价格版本保存在 `openrouter-prices.json`。取自 2026-11-27 的 [OpenRouter Models API](https://openrouter.ai/api/v1/models) 标准公开费率，按精确公开 ID、唯一短名或确切快照型号匹配。无模糊、前缀、批量或相近模型降级。使用当前快照为历史请求做同口径对照，不回放当日价格。标准输入、缓存读取、缓存写入和输出四费率依次为每 Token 的皮美元（10⁻¹² 美元）。缺价保留空，不代表免费。对已报告且可证明为零的数量，费用为零。
- 对有 `min_prompt_tokens: 272000` 覆盖条目的模型，总输入严格大于阈值时才按长上下文档，不能按 Issue 汇总输入判断。标准、长上下文和输入未知的可计费数量预聚合。缺少总输入时，合法缓存计数之和若已严格高于阈值，足以证明长档。无法确定档位时，明确上报的零和跨档相同的确定价格仍可纳入，其余标记未知。调整同档费率只需更新快照。若公示引入新分档或计算口径，应更新投影并明确重建，不能将不适用的费率视为标准费率。对有 UTC 时间表或未支持条件的快照项不套用顶层默认费率，明确展示不适用原因。本版本不支持 UTC 价档，特别不会拿回填入库时间冒充原请求时间。

## 缓存字段契约

老 Tend 的 `CompactTokens` 与 `EstimateUsagePrice` 区分缓存读取、写入和输出，并在请求层扣除缓存项。本次模型行直接显示非缓存输入（扣除读写）、缓存读取、缓存写入和输出。未上报写入的行不显示写入格，明确上报 0 则显示 0。其他缺失项显示未知，有些请求提供则显示已知部分。

只使用 Codex 归一后的 Responses 用量，不直接解释任意供应商原始字段。老 Tend 以供应商区分 Codex 的 `cache_write_input_tokens` 与 TraeX 的 `cache_creation_input_tokens`，本次只使用 Codex 方言，不跨方言推算。OpenAI 的缓存读和写是总输入中分开的收费项。[OpenAI Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching) DeepSeek 的总输入等于 cache hit 加 miss，没有独立写入字段，不能把缺失或非零写入推测为免费。[DeepSeek API](https://api-docs.deepseek.com/api/create-chat-completion/) 对读写和超过总输入等不相容输入，不报价该请求的输入分项。输出独立计价，推理输出不再加价。
