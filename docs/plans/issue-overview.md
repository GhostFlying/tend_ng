# Issue 看板概览

看板卡片打开 `/issues/<id>/overview`。概览沿用 Tend 的内容列、普通文字和链接。标题、阶段、仓库和工作目标来自持久工作记录，长目标可展开。参考旧 Tend 的工作属性与交付入口，以及 Multica 在标题和描述后展示子项的层级。

- 只读 API 按 Issue ID 查询，复用看板的阶段计算和 PR 关联规则。关联列表显示直接子 Issue，以及当前 Issue 树已经登记的 PR 和原件。子项交付标明来源，未同步文件使用现有的可用状态。
- 概览提供看板、原消息和 Issue 对话入口。既有 `/issues/<id>` 继续指向该 Issue 的 Owner 对话，在其页头添加概览入口。消息及回复仍走原 Issue 消息 API，附件使用原下载鉴权和文件 ID。
- 主 Chat 与 Issue 对话在显式 `#message-<id>` 链接打开时，沿现有游标读取到目标消息页后滚动定位。普通打开只读取最新页。回归用例将原消息埋到历史页，在两个视口核对目标可见、分页和轮询。
- 用实际 Server、Runner、SQLite 记录和同步原件验收。通过固定 Agent 输出创建父子 Issue，登记已知的 GitHub PR 并同步一份交付。在宽屏和触屏视口核对标题、阶段、工作目标、子项、PR、下载字节、原消息锚点、原 Issue 消息读写和返回路径。运行 Web 静态检查、构建及看板、Issue Chat、交付的定向回归。
