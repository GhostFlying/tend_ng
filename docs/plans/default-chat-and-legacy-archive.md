# 默认主 Chat 与历史普通会话归档

目标是仅接受默认 `main` 的新普通 Chat 消息。Web、CLI 和公开 API 共用 Server 的消息准入，不改投其他 Chat。正式登记的 Discussion（包括它独立的归档状态）、Issue Owner 对话和讨论转交继续沿用各自契约。

## 实施范围

1. SQLite 升级按旧 `chat_messages` 中的持久 Chat 身份识别候选，排除默认 `main` 以及存在 `discussions` 登记的身份。Issue Owner 对话走独立的 Issue 消息表和入口，Issue 来源消息只是原 Chat 的链接。无需生产 ID、名称约定或手动列举。新增归档登记，不移动或删除消息、附件、关联、操作或待投队列。
2. 新普通发信在原收件事务校验身份。未知目标返回 404，归档目标返回明确的只读错误；已接受且完全匹配的操作重放只返回原回执，不重新入队。历史 Chat 的直接用户回复和新结构化批准受只读边界约束。若原 Chat 已归档，原 Issue 提供显式逐项批准，仍逐项校验 Attention、候选版本和原 Task；可写 Chat 的多待决规则不变。Router、Runner 的原内部回报和已有操作回执独立收尾。
3. 公开消息页标识类型；另提供归档 ID 清单及对应 CLI。未知消息 GET 返回 404，不写入或建立任何历史记录。Web 对非默认普通 Chat 默认不挂载输入框，确认归档后展示历史、附件、原引用、Issue 链接与返回默认主 Chat 入口；不存在时显示明确状态及同一返回入口。
4. 用三条脱敏旧普通会话、普通与已归档 Discussion、默认 Chat、独立 Issue 对话验证升级和重启，核对原消息、附件及关联；用真实 Server/CLI 和浏览器验证准入、历史链接和回执无副作用重放，并用固定 App Server / Runner 回归报告、Owner 与讨论转交。相关旧测试数据按新的会话边界调整。记录真实页面截图、定向检查和审阅。按仓库规则快进推送并核实完整远端 `main` SHA，交付止于合入。

独立审阅补充验证同时存在两个结构化待决项的组合，覆盖客户端逐项选择、过期版本、原 Task、重复回执和无新 Chat 写入。接入最新主干时将普通 Chat 迁移顺延为 v56，保留 v55 的 Issue 标题历史迁移；覆盖从 v54 和 v55 升级。
