# 讨论一键转交与首条用户输入标题

## 目标与边界

- 「转交主 Chat」只由 Web 点击或 CLI 显式调用触发。Server 在 SQLite 登记请求和队列项，原讨论的原生 thread 负责总结。同一讨论的最新真实用户输入边界只对应一次一键转交，刷新、重复提交、丢回执、不同标签页不重复投递。有新用户输入后可发起新的转交。
- 默认不要求预览、确认或指定推进 Issue。讨论 App Server 不可用、原生回合失败或返回不合格摘要时，不投递。重试沿同一请求和原引用快照，独立保留原生尝试。保留预览、编辑、选引用、选目标以及手动填写的路径。手动发送是独立的显式动作。
- 只汇总在原请求前已发生的对话。原生历史是主上下文，持久历史工具按请求边界分页，覆盖旧内容与原生历史恢复。模型把相关结论、理由、约束、待定事项和授权写成自然语言，不套固定小节。Server 使用固定的非授权框架附加点击时的引用快照。主 Chat 仍收到普通用户消息，保留 Router 决策和持久双向回链。
- 空讨论标题是「未命名讨论」。在正常 Chat 用户输入的接受事务中，只由首条输入填充完整的 Unicode 空白归一化标题。手动创建和改名锁定手动来源。回填只处理旧默认标题，保护旧创建及能从旧数据证明的改名。对旧版无改名记录、时间戳无法区分的同名改名，在契约中注明推断限制。
- 不部署、不重启线上服务，不读取或操作生产讨论。提交测试过、独立复核的候选到 origin/main。

## 实现和验证顺序

1. 增加标题来源和快照转交请求迁移。标题回填用原消息 seq 判定首条输入，排除所有草稿内部输入。使用存储单元测试覆盖兼容、全长、空白、首条及并发。
2. 在共享讨论 API 登记/读取/重试同一转交，沿既有草稿隐藏输入、Router 回合和原生尝试调度。完成时在同一事务中写入摘要、主 Chat 普通收件和双向关系。针对快照、尝试围栏、不配置与失败路径增加存储和隔离 fixture 验证。
3. 增加 CLI 一键转交、状态和安全重试。Web 主按钮与状态栏显示进行中、成功和失败，原预览编辑单独打开。列表、侧栏、页头以 CSS 截断持久标题并暴露完整标题。用 Playwright 在临时 Server 实际渲染桌面和手机，保存截图。
4. 用临时 SQLite、临时 Server、隔离认证 Discussion Codex home 和全新合成输入跑真实模型摘要验收，保存输入、模型输出和唯一接收回执。运行 Rust 格式、测试、release 及 Web 安装、类型、单测和构建；整理精确证据，独立复核并回读远端 SHA。

## 独立复核与补充交付

- 自动转交正文由原讨论 Agent 写成 Router 可直接处理的一段任务说明、结论或待决请求。只保留必要理由、授权与约束，不复述聊天、不套五段模板、不把按钮提示或末尾题外话当任务。Server 仍以简短固定提示标明来源和授权边界，并附加当时的引用快照。人工预览仍使用可编辑的旧字段。
- 原生 thread 在输入边界以内时直接复用。若旧请求重试或点击时有未结算回合，且原生 thread 已包含边界外的内容，不能把它直接交给模型。优先从原讨论原生 thread 的边界前分支接续，不能确认该边界或原生历史缺失才从有界的持久讨论记录恢复。复用同一讨论 Agent、配置及工具，不另设 summarizer，不改写原讨论 thread。验证实际原生输入、边界、主线程身份及恢复，不仅检查历史工具。
- 主 Chat 消息保持用户可见，但持久自动转交来源不可作为用户 Attention 答复、工作启动或其他授权写入依据。Router 可直接理解、回报、给出建议或询问；需明确授权才可通过真实用户输入或已审阅的手动转交使用写入能力。
- 失败后的旧操作与当前真实用户输入版本独立显示。操作 ID 覆盖 CLI 部分 2xx 响应解码丢失。人工和自动同 ID 冲突一律返回 409。旧标题迁移把旧普通输入两条 SQL 可能跨秒的 +1 秒视作歧义，更晚且有时间证据的同名改名保留；新手动标记仍无歧义。
- 重跑覆盖尾部题外话的真实模型，并注入晚到原生回复、后续用户回合、丢半截响应、工具错误归因和移动端换版本场景。将修订后的精确提交交同一 Review Task 复核。

## 原生上下文与接收端权限复核

- 在转交登记事务中，保存当时的原生讨论 thread 身份，以及已结算、可见讨论回合的安全尝试前沿。第一个未结算、失败或隐藏回合就截断原生前缀。后续尝试（包括同一转交自身的失败输出）都不得进入下一次模型调用。只在当前 thread 确认未越界时原地新开一轮，能确认原生前缀则从边界前分支，无法确认时用有界持久记录，不改绑关闭或领先的原讨论。
- 由持久转交身份把生成内容送到同一主 Chat 的独立只读接收回合。不用普通 Router 的进程、原生 thread、工具或用户配置；使用已配置的 Discussion 认证及验证后的无网络、零工作区权限，并关闭原生 shell、浏览器、插件、应用、MCP 和其它可写集成。正常用户消息与审阅后的手动转交沿原 Router 路径。需要授权时将问题正常显示在主 Chat，不代答 Attention。服务缺失或隔离校验失败时不回退到普通 Router。
- 新增真实输入探针，覆盖同一失败转交重试、已有原生回合晚到并失败、普通 Router 未收到生成正文、只读接收权限有效、禁用集成及零写入。按实际候选重新执行既有验收。

## 主 Chat 接收数据范围与 Router 续接复核

- 隔离接收模型只收到当前转交和它的 Server 来源说明，不发送主 Chat 的其它消息给 Discussion 的可独立配置供应商。
- 普通 Router 的通用历史重放排除自动转交及其隔离回复。自动转交的正文与可见接收回复在专门的有界背景块中一起提供，显式标记生成来源和非授权属性。同一块既支持已有线程的下一条真人消息，也支持由真人、报告、Attention 或外部事件开启的新线程。直接回复转交或隔离回复时，引用里同时标记该来源。
- 通过隔离真实 App Server 捕获供应商实际请求，并在普通 Router 的已有线程和外部事件新线程中核对最终输入。其余已复核行为、迁移版本和 UI 不变。

- 已有 Router 线程按相邻两条真实用户消息划定续接区间。转交正文或隔离回复只要有一条落在区间内，就在专门的背景块中带入截止当前输入前的完整可见交换。用真实 App Server 的本地供应商 fixture 暂停接收回复，验证较早用户输入看不到后来的回复，下一轮同一线程收到带来源的回复，再下一轮不重复补送。
