# Tend 管理的 Codex 原生会话持久化

## 目标与边界

所有由 Tend 启动的 Codex 会话使用所属服务或 launcher 显式配置的独立 `CODEX_HOME`，创建原生持久会话。不从个人默认 home 查找，也不复制原生记录。保留已有的 thread 复用、受限能力、cwd 和 Run 恢复规则。只改会话持久化及直接相关的用量，不部署、不运行生产回填。

## 实施

1. 核对 App Server 入口。统一强制持久化的创建请求，包含飞书研判、Router、普通讨论、转交总结、隔离接收、Runner 及有界 fork。续接与只读恢复保留原 thread、turn 与所属 home，避免隐式默认值。检查 launcher 与实际启动配置的对应关系。
2. 飞书保持独立 home、受限权限、模型配置和每次研判新 thread。登记 attempt、原 home/rollout 绑定和 App Server 确认的本次模型。用量仍按原始 response ID 去重，保留实际响应模型优先级与未知字段。
3. 让原有显式全量历史回填读取新研判的绑定，区分旧 ephemeral、新原件缺失及其他缺口。旧记录仅使用已留存、可精确归属的计量证据，不从当前配置、累计数、文案或时间相近推断。需要查证现存记录时只读取最小必要的计量元数据，不改生产。
4. 更新工程、设计与运维契约，明确 home 权限、保存、按原 thread/turn 查证、历史覆盖及与既有飞书产品数据的边界。

## 验证与交付

- 在隔离的临时 home 用真实 Codex App Server 和本地 Responses 上游核对文件、身份、重启后原身份查找和新飞书全量回填，核对模型归属、未知字段和去重。使用合成内容。
- 针对各创建与恢复入口补定向测试，覆盖现有隔离、限定前缀、共享/替代执行与恢复行为。说明真实 App Server 和 fixture 分别验证了哪些行为。
- 做独立候选复核与仓库门禁要求的定向检查后按仓库约定推进到 `origin/main`。交付止于远端完整 SHA 与验收证据。

## 审阅后的收口

- 提取启动和历史读取共用的原件目录校验。Discussion 在校验时排除个人 home 的字面路径和解析目标，且不把解析目标作为可附加的工作目录。所有启动在发送原生请求前拒绝别名或非目录的 `sessions`、`archived_sessions`。
- 飞书以独立 attempt 绑定保存启动时所选模型。只在用量投影中将它用于原生模型未知的请求，合并和保存逐请求证据时不注入同等级的回合模型。验证实时与回填两种到达顺序、原生冲突仍保持未知、既有用量不重计。
- 用定向回归和真实 Codex 重验本次改动涉及的入口，再提交同一 Review Task 复审。

复审补查直接绑定路径。回填必须先验证原件所属 Codex home 的布局，再打开绑定文件或索引该 home，不沿现有路径上的符号链接读取。已登记路径的所属 home 优先于当前服务配置，文件归档后在同一个原 home 按 thread 查找。回归用旧 home、配置漂移和链接替换证明错误布局不会导入原生键，恢复正常布局仍能按原身份重扫。
