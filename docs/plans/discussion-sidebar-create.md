# 讨论入口、站内导航与 Issue 详情清理

## 目标与边界

- 将完整桌面侧栏（≥1024px）中「讨论」下方的整行主按钮换成导航右侧始终可见的加号。链接只打开讨论首页，加号以「新建讨论」为可访问名称，只新建空白讨论。保留原生键盘操作、创建错误提示和请求幂等行为。
- 加号使用独立的 40×40 CSS px 点击区，和既有 40px 导航行对齐，不叠在链接上。窄窗图标栏与手机继续在讨论目录上提供原有的新建按钮。
- 对话、讨论目录、讨论详情及其他既有 Web 页面之间的普通站内链接在同一文档内导航。保留 URL、后退/前进、深链、原生片段跳转、修饰键和新标签行为；不把下载、外站或未识别路径接管成页面路由。
- 只移除 Issue 详情标题下的「带入讨论」快捷创建。保留主 Chat 原消息上的入口，也保留讨论页主动搜索和添加 Issue 引用的能力。
- 不改最近讨论的选中规则、归档和恢复语义、服务端 URL、API、存储和 CLI。交付止于合入，不部署，不使用线上讨论或真实模型，不操作 #82。

## 实施与验证

1. 在全局桌面导航中把「讨论」链接与新建按钮并列放置，复用现有创建流程，移除最近讨论前的旧按钮。
2. 用 History API 读取当前路由，保留真实 `href`，只接管普通点击。按会话身份挂载对应内容，继续使用原消息片段和回读逻辑。同一文档内切换后，共享尚未回执的发送，禁止重复 POST，消息收件和重试继续沿原操作 ID。
3. 用临时 SQLite、合成讨论和 App Server fixture 启动实际 Server。检查按钮、键盘、hover/focus、手机触控、归档/恢复与唯一选中态。记录同一个文档和零 document 请求，覆盖后退/前进、直接打开 URL、原生新标签、发送回执延迟后切走再返回以及消息唯一。检查桌面和手机 Issue 标题区无快捷入口，再从讨论页主动附加 Issue 引用。
4. 运行 Web 类型、lint、格式、单测和构建，并复核受影响的 Chat、Issue 详情和讨论浏览器验收。保存 1440×960 桌面与 390×844 手机实测截图，核对完整交付的远端 main。

## 审阅回归

- 当浏览器存储写失败且发送回执在另一个页面丢失时，在当前文档中保留待确认正文、引用和操作 ID。返回后明确重试，断言两次请求使用同一身份且 SQLite 只记一条消息。
- 讨论创建或归档状态修改成功后，即使原页面已卸载，也让当前的列表和同一讨论详情重新读取。延迟真实 POST/PATCH，覆盖切换目录、离开详情后 Back，以及相同 URL 的两条历史记录之间后退后仍可前进。回执到达时不误跳页。
- Agents 的过滤和详情选择以 URL 为准。验证同路径再次进入清空筛选、浏览器 Back 恢复原查询、Forward 再清空。
