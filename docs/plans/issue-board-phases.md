# Issue 看板阶段与旧版布局

看板默认展示顶层 Issue，卡片读整棵树的工作事实。CLI 仍可分页查询全部或单个 Chat 的 Issue。Issue Chat 保留父子留言、PR 与执行详情的入口。

Router 可以登记一份待安排 Issue，沿原 Chat 保存目标和执行要求。记录时没有执行 Task。用户要求开工时，Router 或 CLI 沿原 Issue 激活一次，复用已有任务派发机制。直接交代现在做的工作继续即时派发。重复调用沿原 Issue 和操作查证。

按业务终态、实际运行、待安排、可安排工作和登记等待的顺序分列。已完成和已取消沿 Owner 的业务结算。开放的 Issue 树有任一实际 Run 即为进行中。停妥以后，有可安排的 Task 或待处理的原输入时进入待推进；整棵树只等已登记的事实或回复时进入等待中。未结案且缺少明确等待的 Issue 仍在待推进。领取、容量与工作区独占沿已有执行契约。

需要用户处理的已发布 Attention 在非取消卡片显示「待你决定」，点击回到原 Chat。用户检查属于这类决策。普通审阅按实际运行或等待分列。已完成的卡片仍可显示正在收尾的子执行。

视觉以旧 Tend 的桌面和窄屏看板为基准。桌面使用六列、状态圆点、计数、浅色列底与细边框卡片，保留每列的空状态。普通列及展开的「已取消」列沿旧 Tend 主干共用 256px 最小宽度。「已取消」默认展开，标题横排，用户可点击列名收起为 44px，浏览器保留选择。空间不足时在列区内独立横向滚动。窄屏采用横向状态标签并一次显示一列，选中列填满可用区域且同样至少为 256px。卡片标题用旧 Tend 的正文大小、字重与次级正文色，仓库和进展用更浅的辅助色。卡片直接打开 Issue，对用户的决策保留明确入口。

使用现有 App Server fixture 覆盖记录、重复提交、原 Issue 准入、子 Run 实际运行与停妥、待推进与等待优先级、Attention 和终态。复跑看板 PR 和真实浏览器入口，检查列、卡片、移动标签及空状态。在旧址更新 Server 和 Web 后再次验证。

看板样式调整沿现有 Web fixture 复验。桌面测试首次默认展开、收起后刷新仍保留选择，并在空间不足时核对展开、收起两种状态的实际列宽和横向滚动。窄屏检查仍可通过标签访问该列，视口小于列宽时在列区内滚动。发布仅更新静态资源，在旧址复查列宽并截取实际桌面和窄屏渲染。

## 入列顺序与分页

六列都按最近一次进入**当前阶段**的时间从新到旧排列。新卡片记录首次可见阶段。离开后重入同一列重新计时。留言、Attention、PR/CI 等更新只有在真的改变派生阶段时才影响顺序。业务写入以 Server 同一事务可见的阶段为准，子项合并窗口导致的纯时间转列用实际截止时间。

历史入口无法证明时保持未知，排在所有已知入口之后，不用 Issue 创建顺序、修改时间或迁移时间推测。时间相同（含同为未知）时按不变的 Issue ID 字典序降序。

Server 在截页前按同一个全局键排序，桌面和窄屏仅将本页按阶段分组，各列保留服务端顺序。看板、全部 Issue 和按 Chat 的 Issue 列表使用 `next_before` 返回的字符串，并原样传入 `?before=`。格式为 `v1.<入列毫秒>.<Issue ID>`，其中 0 只表示未知。旧数字光标不兼容，从第一页重启。分页读取实时视图，翻页期间发生转列可改变后续页面，回第一页可重新定位。 [实现与验证范围](issue-board-stage-entry-order.md)

## 已取消卡片去除状态徽记

仅在看板卡片渲染时，对 `cancelled` 阶段省略进展、Attention 和 PR/CI 状态文字。保留仓库、标题与 Issue 历史入口、PR 链接和已取消列。其他阶段的卡片保持原样。不改 API、保存的历史记录、Attention、报告、Task 或通知，不操作生产数据或部署。

用组件测试比较带有相同运行进展、Attention 和 PR 状态的已取消、已完成与进行中卡片，并检查保留的链接。运行 Web 检查和构建，再用合成数据验证实际构建在 1440×1000 和 390×844 的看板渲染、窄屏溢出和历史入口，提交截图作为交付附件。
