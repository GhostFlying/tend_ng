## 实施顺序

1. 在专题产品契约记录身份、事项键、首包、只读补读及版本/保留语义。保留旧 JSON 读取和显式版本快照；关联仅基于当前可核对来源，不对旧卡做全量重组。
2. 扩充采集材料，保留创建/编辑时间、本人/作者/提及键、回复和结构化引用、来源降级及读取缺口。沿原有扫描与限页恢复保存事项材料，去掉时间接近导致的自动合并。锚点及直接关系单列，按关系筛前 2、后 4。对显示字段与事实字段分别比较，通过版本拒绝迟到结果。
3. 在原受限 App Server 增加两个动态只读工具。Server 持有 provider 身份、每次研判的范围、截止时刻及游标；研判仅引用实际可读材料。不跨会话展开，不暴露凭据、写操作或宽口搜索。列表给两句、可选待确认和来源指引，区分本人行动、他人接手、知会、已答复/完成/撤回及未知。显式带入继续沿现有版本/回执。
4. 用 Rust 定向测试、真实本地 Server、飞书 CLI / App Server 合成 fixture，以及桌面/手机 Chromium 验证。覆盖同群独立事项、指代补读、截止与分页、同名、未来/撤回、名称和重复不重判、迟到版本、忽略和旧快照、无自动推送。记录浏览器交互并保存最终渲染。提交准确候选并独立复审，按仓库门禁合入并核对远端 main 的完整 SHA。

## 边界

不接触个人飞书、真实 Chat 或生产研判材料，不运行真实模型，不发送飞书消息，不部署。不新增评测项目。仅合成例子进入 fixture。
