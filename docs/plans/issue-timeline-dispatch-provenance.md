# Issue 时间线的派发来源与确认接手

## 目标与边界

- 区分主会话派发、其他 Chat 派发、Issue 委派与 Runner 确认接手。主会话部署时选用名称 `Tend`，通过 Server 启动参数显式设置并随新派发持久保存。未指定或没有历史证据时仅显示主会话来源。Issue 委派显示实际发起者，不从接收者、当前 Owner 或配置反推。
- 原派发正文、操作身份、原 Chat 消息、引用、回复与转达语义不变。接手只展示经验证的 Runner 接受回执，不是用户可回复的留言，也不表示 Run 已启动。
- 每个新确认的 assignment 最多一条接手事件，在接受回执事务内以原 assignment 身份追加至时间线。续接若有新 assignment 和新接受回执，可以有新的接手事件。同一 assignment 的后续 Run 或重放不新建事件。旧库没有可靠的确认时刻或时间线位置，不回填接手事件。
- 只交付 Tend NG 源码到 `origin/main`。不发布、不改生产配置或数据。仅对生产 Router 可公开的身份字段与 SQLite 结构、聚合计数做只读核验。

## 实现与验证

- 保存明确的派发名称证据，保留历史消息序号、引用和索引。API 将派发来源与可选名称一起返回。接手沿 Issue 消息原时间线分页，不写入 Runner 留言或输入队列。
- Rust 覆盖旧库迁移、回执写入与重放。隔离 Server、Runner 和模拟 App Server 验收带名/缺名派发、子委派、取件与确认区分、丢回执和对账重放，并检查原目标及链接。
- Playwright 打开真实构建，检查未确认与已确认、名称来源及链接。保存 Chromium 1440×1000 与 390×844 截图。运行工作区 Rust 测试/构建以及 Web 类型、lint、格式、测试和构建检查。

独立审阅发现顶层 Issue 也可来自其他 Router Chat，绑定审阅可由同级作者 Issue 委派。按派发保存的原 Chat 区分主会话与其他 Chat，Issue 委派采用不暗示树关系的来源类型。隔离验收分别覆盖非主 Chat 和同级绑定审阅。
